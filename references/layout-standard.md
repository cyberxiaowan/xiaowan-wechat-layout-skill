# 移动端排版标准

以下数值是适合中文公众号长文的默认起点，不是不可修改的品牌规范。若用户已有稳定视觉值，以用户值为准。

## 视觉变量

| 用途 | 默认值 |
|---|---|
| 页面背景 | `#fdfdf8` |
| 正文 | `14px / #595757 / line-height 1.9–2` |
| 正文强调 | `#23251d / 700` |
| 章节强调色 | `#b17816` |
| 深色结构 | `#1e1f23` 或 `#23251d` |
| 次要文字 | `#65675e` |
| 弱化文字 | `#9ea096` |
| 浅灰底 | `#eeefe9` |
| 暖色重点底 | `#efe4cc` |
| 边框 | `#bfc1b7` |
| 圆角 | 约 `6px` |
| 页面内边距 | 约 `14px` |

建议层级：

- 章节编号：约 `34px`；
- 章节标题：约 `22px`；
- 案例标题：约 `19px`；
- 趋势小标题：约 `18px`；
- 图注：约 `11px`。

## 首屏

首屏顺序：

1. 刊头与日期；
2. 中文主标题；
3. 用户自有识别资产；
4. 一句副标题；
5. 编者按标签；
6. 2～3 个短段落；
7. 一条完整重点句。

个人识别资产应清楚但不抢标题。不要使用本 Skill 自带的通用笑脸，也不要复制他人的 IP 形象。

## 大章节

采用 `01 + PART + 章节标题 + 英文副标题`。

- 标题本身就是锚点；
- 标题下不加横线；
- 编号与标题之间不加竖线；
- 大章节前留白约 `56–62px`；
- 标题到首个内容块约 `34–38px`。

## 案例

采用：

- 深色 CASE 药丸；
- 案例名同排；
- 机制副标题单独一行；
- 正文；
- 拼图与图注；
- 判断或问题；
- 收束。

案例间距约 `48–52px`。不使用左侧时间线，不用整块外框包住每个案例。

## 文字与断行

- 正文不要硬编码换行。
- 一个段落尽量只承担一个观点。
- 标题与金句按完整语义分行，行长尽量接近。
- 第二行若只剩 2～3 个字，应改写标题。
- 长重点句换行后仍须处于同一个强调容器。
- 不对每段自动加下划线。
- 不在同一句同时使用粗体、底色与下划线。

## 装饰预算

建议全文最强视觉锚点不超过 5 处。

- 外框用于建立完整区域，不用于包住每个小模块；
- 横线只用于确实需要结束或分隔的地方；
- 色块只承载完整观点；
- 药丸标签用于 CASE 或动作名；
- 删除装饰后，要确认章节仍可辨认。

## 图片组合

| 内容类型 | 推荐组合 |
|---|---|
| 线下空间/IP 餐饮 | 场景横图＋产品/甜品双图 |
| 明星服饰 Campaign | 横向 Hero＋下方两张等宽全身图 |
| 毛绒/领养机制 | 两张正方形横排：角色阵容＋套装/证书 |
| 包装/无障碍产品 | 产品主图＋握持/按压动作 |

原则：

- 图片进入 HTML 前先合成为静态拼图；
- 同排图片等高、对齐、间距一致；
- 人物图要能证明服装版型；
- 产品图要让产品和关键动作足够大；
- 图片数量由证据需要决定，不机械追求一致；
- 图注采用：`画面内容。图片来源：品牌／媒体`。

## 结尾

建议顺序：

1. `/// END 最后`；
2. 两段收束；
3. 完整金句；
4. 来源；
5. 居中作者介绍；
6. 点赞/在看/收藏 CTA。

CTA 三项等宽，不使用复制后容易丢失的复杂 SVG。

## 封面

- 横屏主封面建议 `2100×900`；
- 平台标题负责说清案例与主题；
- 封面金句负责提供意义判断；
- 主标题两行以内优先，并充分使用横向空间；
- 不要为了方形裁切把所有内容挤进中央安全区；
- 若需要方形小图，单独使用作者自己的识别资产。
