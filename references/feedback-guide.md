# 排版反馈处理指南

用户通常不会使用专业设计术语。收到反馈后，先翻译成问题层，再局部处理。

| 用户反馈 | 问题层 | 优先处理 |
|---|---|---|
| “文章散／不知道在说什么” | 内容逻辑 | 核心命题、章节职责、证据链与顺序 |
| “不像我／风格不对” | 个人审美 | 回看最终发布稿、参考图和个人风格卡 |
| “框架感不强” | 层级 | 章节字号、颜色、粗细、章节前留白 |
| “太拥挤” | 间距 | 缩短首屏、拆段、拉开相邻模块 |
| “线太多” | 装饰 | 删除无功能横线、竖线与边框 |
| “删得太过了” | 锚点 | 恢复少量已验证的刊头、编者按或整句重点 |
| “标题下面为什么有线” | 结构 | 删除将标题与自身内容割开的分隔线 |
| “第二行只剩几个字” | 文字 | 改写语序、长度或语义分行 |
| “高亮看着难受” | 强调 | 覆盖完整短语或整句 |
| “图片很普通” | 证据 | 补产品、动作、机制或人物全身 |
| “图片不规整” | 拼图 | 预合成、等高、统一比例和边距 |
| “之前那版更好” | 回滚 | 恢复明确被认可的组件 |
| “复制后丢图/乱码” | 兼容 | 替换本地路径和复杂图标 |

## 修改纪律

1. 先复述你识别到的问题层。
2. 只改该层，不顺手调整用户未反馈的区域。
3. 保留用户已经明确认可的部分。
4. 每轮保留前后截图，避免凭记忆重做。
5. 删除线条后检查结构是否仍然清楚。
6. 增加重点后检查语义是否被切碎。
7. 修改一张图片后检查整组是否仍规整。
8. 若用户在公众号编辑器里又做了人工调整，以最终发布值为准。
9. 内容逻辑问题先给诊断；未经授权，不把排版反馈扩大成全文改写。
10. 参考图只提取层级、密度、节奏和装饰方法，不复制他人 IP 与完整版式。

## 稳定偏好与单篇处理

只有满足以下任一条件，才写入长期规则：

- 用户在两篇以上文章中做了同样调整；
- 用户明确说“以后都这样”；
- 该调整修复了确定的平台兼容问题；
- 该调整来自公众号后台或手机真实预览。

否则记录为当前文章特例，避免把一次性的设计变成所有文章的硬规则。长期沉淀的目标是形成用户自己的内容偏好与个人风格卡，不是越来越接近 @小晚不在。
