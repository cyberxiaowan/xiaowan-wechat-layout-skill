# 公众号长文工作流

## 状态

`BRIEFED → FROZEN → ASSETS_READY → STRUCTURED → HTML_READY → PASTE_READY → LEARNED`

不要跨阶段混改。正文没有冻结，不进入精排；公众号后台与手机预览是最终权威。

## 1. BRIEFED｜建立任务卡

至少确认：

```text
平台标题：
封面金句：
文章类型：
核心读者：
希望读者记住：
正文状态：草稿／最终版
允许修改：正文／结构／排版／配图／封面
个人识别资产：
参考旧稿或已发布截图：
```

先检索用户已有文章、视觉资产和历史修改记录，不要从空白模板开始猜。

## 2. FROZEN｜冻结正文

1. 将文章归一化为：首屏、编者按、章节、案例/论点、趋势、动作、结尾、来源、作者信息。
2. 保存唯一最终正文。
3. 建立段落清单，标记事实、数字、专有名词和图片来源。
4. 正文冻结后，排版阶段不得为了版面好看擅自删句。

## 3. ASSETS_READY｜建立证据型配图

每个案例填写：

```text
正文判断：
图片必须证明：
首选来源：
需要画面：场景／产品／人物全身／使用动作／机制细节
拼图结构：
图注：
```

优先官方 Campaign、产品页、品牌新闻稿和可靠媒体。若一张图不能帮助读者理解正文，就不要因为“版面空”而加入。

## 4. STRUCTURED｜完成手机端视觉脚本

1. 首屏只放一套完整题图卡。
2. 明确 `01/02/03` 大章节。
3. 每个案例固定为：CASE 标签、案例名、关系/机制副标题、正文、图片、判断与收束。
4. 每个案例最多 1～2 处行内强调；每章最多一条完整重点句。
5. 检查标题孤行与不自然断行。
6. 检查线条、边框与色块是否抢占同一层注意力。

## 5. HTML_READY｜生成 HTML

1. 使用 `gzh-design` 生成公众号兼容的基础 HTML。
2. 应用移动端视觉变量。
3. 多图预先合成静态拼图。
4. 输出干净版、预览复制版和发布稳定版。
5. 以约 390px 视口检查完整长截图。

## 6. PASTE_READY｜真实粘贴检查

复制进公众号后台后检查：

- 个人识别图片是否存在；
- 所有图片是否正常；
- 拼图是否错位；
- 图标是否乱码；
- 正文字号、颜色与行距是否被改写；
- 是否出现异常空白；
- 手机端标题和重点句是否自然换行。

发现问题只修改对应层，不重新设计整篇。

## 7. LEARNED｜把反馈写回系统

比较本地预览、公众号后台与最终发布截图，将修改分为：

- 单篇特殊处理：只留在本项目；
- 稳定视觉偏好：写入排版标准；
- 必查问题：写入发布清单；
- 固定工作顺序：写入本流程；
- 作者头像、IP、署名与封面：保存为用户自己的资产，不随公开 Skill 分发。

判断标准：下一篇能不能少解释一次、少返工一轮。
