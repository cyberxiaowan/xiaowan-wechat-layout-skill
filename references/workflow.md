# 公众号内容与排版共创工作流

## 状态

`BRIEFED → LOGIC_DIAGNOSED → FROZEN → STYLE_DEFINED → ASSETS_READY → STRUCTURED → HTML_READY → PASTE_READY → LEARNED`

不要跨阶段混改。正文没有冻结，不进入精排；个人风格没有定义，不把通用默认值冒充成用户审美；公众号后台与手机预览是最终权威。

## 三种入口

### 完整共创

适用：用户提供初稿、参考图，并允许优化后排版。

从 `BRIEFED` 开始，先诊断内容逻辑和审美方向。诊断结果经用户确认后再修改正文和生成 HTML。

### 正文已冻结

适用：用户明确说“这是最终正文”“不要改文字”。

从 `FROZEN` 开始。内容逻辑只用于标记章节职责、图片证据和风险，不改正文。

### 已有 HTML

适用：用户要求审美诊断、移动端优化或修复公众号粘贴问题。

从 `STYLE_DEFINED` 或 `PASTE_READY` 开始。先锁定已经认可的区域，只修对应问题层。

## 1. BRIEFED｜建立任务卡

至少确认：

```text
文章类型：
目标读者：
希望读者记住／做到：
正文状态：草稿／最终版
允许修改：逻辑／顺序／标题／正文／排版／配图／封面
个人识别资产：
参考旧稿、已发布截图或参考图：
明确不喜欢：
```

先检索用户已有文章、视觉资产和历史修改记录，不要从空白模板开始猜。

## 2. LOGIC_DIAGNOSED｜完成内容逻辑卡

仅在用户允许结构诊断时执行。读取 `content-logic.md`，输出：

- 目标读者与阅读任务；
- 一句话核心命题；
- 当前阅读路径；
- 每个章节的职责；
- 重复内容与证据缺口；
- 建议顺序；
- 需要作者决定的问题。

先给诊断，不默认给全文改写。用户确认后，才按授权范围调整。

放行条件：知道文章为什么值得读、各章节为什么存在、结论由什么证明。

## 3. FROZEN｜冻结正文

1. 保存唯一最终正文；
2. 建立段落清单，标记事实、判断、例子、动作、数字和图片来源；
3. 确认平台标题与正文标题；
4. 正文冻结后，不为了版面好看擅自删句。

## 4. STYLE_DEFINED｜建立个人风格卡

读取 `aesthetic-diagnosis.md`，结合用户自己的最终发布稿、参考图、品牌资产和明确反馈，确认：

- 整体气质和内容密度；
- 正文、标题、章节和图注层级；
- 色彩与页面底色；
- 强调方式与频率；
- 装饰预算；
- 图片比例、拼图和图注；
- 个人识别资产；
- 首屏与结尾任务；
- 明确不要的视觉元素。

若用户没有偏好，可暂用 `layout-standard.md` 的值，但必须标为“第一版起点”，不能称为用户风格。

## 5. ASSETS_READY｜建立证据型配图

每个内容板块填写：

```text
正文判断：
图片必须证明：
首选来源：
需要画面：场景／产品／人物／过程／动作／机制细节
拼图结构：
图注：
```

优先官方 Campaign、产品页、品牌新闻稿和可靠媒体。若图片不能帮助读者理解正文，不要因为版面空而加入。

## 6. STRUCTURED｜完成手机端视觉脚本

1. 根据内容逻辑卡决定首屏要完成的任务，不固定套用组件；
2. 标出大章节、子章节、重点句、图片和结尾；
3. 依据个人风格卡设定强调与装饰预算；
4. 检查标题孤行、段落密度和图片占屏；
5. 检查相邻屏幕是否连续拥挤或连续空泛；
6. 只看结构稿，也能理解阅读路径。

## 7. HTML_READY｜生成 HTML

1. 调用 `gzh-design` 选择与文章和个人风格卡相符的主题；
2. 应用用户偏好与本 Skill 的覆盖规则；
3. 多图预先合成静态拼图；
4. 输出干净版、预览复制版和发布稳定版；
5. 运行底层 HTML 校验；
6. 以约 390px 视口检查完整长截图。

若 `gzh-design` 的自动目录、逐段下划线、引言卡或装饰与个人风格卡冲突，以个人风格卡为准。

## 8. PASTE_READY｜真实粘贴检查

复制进公众号后台后检查：

- 个人识别图片是否存在；
- 所有图片是否正常；
- 拼图是否错位；
- 图标是否乱码；
- 正文字号、颜色与行距是否被改写；
- 是否出现异常空白；
- 手机端标题、重点句和段落是否自然换行；
- 逻辑层级是否仍然可见。

发现问题只修改对应层，不重新设计整篇。

## 9. LEARNED｜把反馈写回系统

比较本地预览、公众号后台与最终发布截图，将修改分为：

- 单篇特殊处理：只留在本项目；
- 内容习惯：写入作者自己的内容逻辑偏好；
- 稳定视觉偏好：写入个人风格卡；
- 必查问题：写入发布清单；
- 作者头像、IP、署名与封面：保存为用户自己的资产，不随公开 Skill 分发。

判断标准：下一篇能否少解释一次、少返工一轮，而不是是否越来越像 @小晚不在。
