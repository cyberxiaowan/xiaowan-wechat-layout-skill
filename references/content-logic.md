# 公众号内容逻辑诊断

## 目标

帮助作者看清文章是否完成自己的传播任务。先诊断，再建议；未经授权不直接重写全文。

## 一、先识别文章任务

建立内容逻辑卡：

```text
文章类型：
目标读者：
读者当前状态：知道什么／误解什么／缺少什么
希望读者读完获得：理解／判断／方法／行动／情绪
一句话核心命题：
作者独有证据：经历／案例／数据／过程／观点
允许调整：顺序／标题／段落／措辞／不改正文
```

如果无法用一句话说清核心命题，先不要精排。

## 二、五项诊断

### 1. 阅读理由

- 开头是否迅速交代“为什么现在值得看”；
- 是真实问题、冲突、结果或个人经历，还是空泛背景；
- 首屏读完后，读者能否预测文章会解决什么。

### 2. 章节职责

为每个章节写一句职责说明：它是在提出问题、解释原因、提供证据、给出方法，还是完成收束。

若两个章节职责相同，判断是合并、换证据还是调整顺序，不靠换标题制造差异。

### 3. 推理与证据

- 事实能否支持判断；
- 个人推测是否标明边界；
- 案例是否大众可理解，并真正承担不同论证角色；
- 图片、数据、过程或亲历是否补足可信度；
- 结论是否在前文已经被证明。

### 4. 信息增量

逐段标记它提供的是新事实、新解释、新关系、新方法还是重复表达。只有情绪加强、没有信息增量的段落，提示作者压缩或合并。

### 5. 结尾任务

结尾根据文章任务选择：

- 观点文：完成判断；
- 教程：让读者知道下一步怎么做；
- 案例复盘：提炼可迁移的方法；
- 个人复盘：说明经验如何改变后续选择；
- 访谈：留下人物最重要的矛盾或价值。

不要所有文章都使用同一种口号式金句。

## 三、不同文体的重点

| 文体 | 优先检查 |
|---|---|
| 品牌案例／行业观察 | 共同母题、案例分工、事实与推测、可迁移动作 |
| 教程／操作指南 | 使用场景、前置条件、步骤顺序、失败点、完成标准 |
| 观点／深度分析 | 核心命题、反方或限制、证据链、结论边界 |
| 个人复盘 | 真实情境、关键选择、结果与代价、经验如何改变行动 |
| 访谈／人物 | 人物矛盾、关键事件、原话证据、作者观察与人物表达的边界 |
| 清单／盘点 | 选择标准、分类依据、差异、适用对象，不只是罗列 |

## 四、输出格式

先交付诊断，不直接给改写稿：

```text
核心命题：
当前阅读路径：
最成立的部分：
主要逻辑问题：
重复或可压缩处：
缺失证据：
建议章节顺序：
需要作者决定的问题：
```

用户确认后，才按授权范围调整标题、顺序、段落或正文。修改时保留作者的语气、经验和不确定性，不将文章改成通用报告。
