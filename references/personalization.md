# 使用者配置与配图机制

## 首次使用与复用
先读取文章、素材和已有项目配置。个人配置放在用户工作目录 `.wechat-layout/profile.json`，不要放进安装目录或公开仓库，避免安装更新覆盖、私人信息随Skill分发。测试使用输出目录下独立 `profile.json`，不覆盖真实账号。

配置包含：首屏模式、栏目名称、署名、个人介绍（逐行原文）、公众号链接或名片、IP本地路径、主题色（正文色/深色/强调色/边框色；默认不设置页面或模块底色）、来源展示方式、配图偏好。缺少个人信息时省略对应模块，不填作者身份或虚构履历。只有明确为测试账号时才可拟定，并在预览外壳标注。沿用已确认配置；本次覆盖默认只影响本篇，用户说以后都这样才更新长期配置。

首次只一次性询问无法从材料确定的首屏和个人身份偏好；不用用户填写字号段距。默认配色沿用小晚预设，也可按用户品牌改色；两版必须同时应用同一配置。用户提供参考图时先提取已有信息，不重复问。

用户流程：提供文章及素材 → 补齐必要首次配置 → 正文排版与必要配图 → 阅读验证 → 封面、简介及发布准备 → 预览局部调整 → 按授权存入公众号草稿并读回检查。完整任务衔接 [visual-delivery.md](visual-delivery.md)；仅请求HTML则交到预览，不擅自操作账号。缺图时先完成不依赖图片的部分，不为配置表阻塞全部工作。

## 配图按作用选择
已有素材优先。截图/实物图用于证据，解释图用于复杂关系，拼图用于同组比较；图片不能仅为打断文字而存在。原图有来源时保留，新增解释图标注为整理示意，不能冒充原始证据。不机械规定数量，不随意移除已有图。

给每张候选图记录对应段落、用途、出处和可读性。图片有大量小字时检查手机实际渲染：必要时拆为主图和局部图，保留顺序，不把整屏密集截图压成不可读缩略图。多图只有在拼合后仍清晰且确属同组时合成，不强制合并所有图片。缺少关键素材时具体说明需要什么；外部查找或生成遵循用户本次范围。纯排版不自动变成图片创作项目。

## 身份与来源独立
账号个人介绍是排版账号身份，文章作者署名是版权与内容归属；转载不能用账号配置替换原作者。资料来源随文章变化：外部找图就近标出处，同源原图可文末统一署源；原有必要图注保留，参考资料按需文末汇总；没有来源信息就不硬加栏目、不编造。正文自然的事实归属仍保留。

主题颜色可配置，但层级、对比度和间距规则不变。应用新配色后检查正文可读性、标题、底部强调、边框、黑栏与作者区，不能只改大标题。顶部IP、栏目名、底部介绍各自可省略，不绑定首屏模式。
